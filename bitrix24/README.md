# WAIX + Bitrix24: событие сделки → WhatsApp

Интеграция через REST API Bitrix24 и серверный обработчик/n8n. Это рецепт для интегратора, не установленное приложение Маркета. Доступность REST и роботов зависит от тарифа Bitrix24.

1. Создайте исходящий вебхук Bitrix24 для события `OnCrmDealAdd` или нужного бизнес-события. Обработчик должен проверять секрет приложения (`auth.application_token`) и разрешённый портал. Не принимайте URL для дальнейших запросов из тела события: домен своего портала задайте в конфигурации.
2. Событие передаёт идентификатор, а не все поля сделки. Прочитайте ID из `data[FIELDS][ID]` и получите сделку через `crm.deal.get` либо `crm.item.get` с `entityTypeId=2`.
3. Найдите связанный контакт и его телефон. Для нескольких контактов определите правило выбора получателя. Нормализуйте телефон в E.164, проверьте согласие на WhatsApp и отсутствие отказа от сообщений.
4. Сохраните событие в своей очереди с уникальным ключом «портал + сделка + тип уведомления + версия бизнес-события» и отдельным UUID для Idempotency-Key. Повторный вебхук должен находить ту же запись.
5. Передайте в n8n `order-notification.json` поля `event_id`, `phone`, `order_number`, `whatsapp_consent`. Вызовите его только с серверным X-Workflow-Key. Либо отправьте шаблон непосредственно через один из SDK WAIX.
6. Сохраните `data.id` в поле сделки или отдельной таблице интеграции. Обновляйте статус по подписанным вебхукам WAIX. Не отмечайте «доставлено» по HTTP 202.

Bitrix24 не обязан отправлять X-Workflow-Key в формате нашего n8n-шаблона: исходящий вебхук сначала принимает ваш адаптер, проверяет токен и только затем вызывает защищённый workflow. Это также защищает от повторных CRM-событий и произвольных получателей.
