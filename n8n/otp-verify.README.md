# Проверка OTP через WhatsApp

[Все сценарии n8n](README.md) · [JSON для импорта](otp-verify.json)

## Подготовка

Импортируйте `otp-verify.json`. Создайте входящий Header Auth `X-Workflow-Key` и отдельный исходящий Header Auth `Authorization: Bearer YOUR_KEY`. Ключ WAIX должен иметь право `otp:verify`. Описание всех узлов: [схема сценария](README.md#что-делает-каждый-узел).

Используйте ключ того же OTP-проекта, который отправил код. `id` берите из серверной сессии, а `code` — из ввода пользователя этой сессии.

## Входные данные

Сервер отправляет POST на Test URL или Production URL из вашей установки n8n, с заголовком `X-Workflow-Key` и `Content-Type: application/json`:

```json
{"id":"CHALLENGE_UUID_FROM_SEND","code":"123456"}
```

Ваш сервер проверяет принадлежность ID сессии и ограничивает попытки по аккаунту и IP. Только успешная проверка WAIX позволяет выдать сессию приложения. Истёкший или неверный код не должен давать доступ.

## Ответ и ошибки

Сохраняйте HTTP-статус и результат API. Sandbox не отправляет реальные сообщения; рабочая отправка зависит от доступности тарифа и одобренного отправителя.

Неверные поля отклоняются до обращения в WAIX. Ошибки `401`/`403` требуют проверки ключа и прав. Для `429` учитывайте `Retry-After`. Проверка неверного кода расходует попытку. Не настраивайте бесконечные автоматические повторы; при истечении срока запросите новый код через сценарий отправки.

Проверьте сценарий с тестовыми данными, затем включите его и переведите backend на Production URL. Ключи и URL внутреннего вебхука не должны попадать в браузер или общие логи.
