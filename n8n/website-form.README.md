# Форма сайта → сообщение WhatsApp

[Все сценарии n8n](README.md) · [JSON для импорта](website-form.json)

## Подготовка

Импортируйте `website-form.json`. Создайте входящий Header Auth `X-Workflow-Key` и отдельный исходящий Header Auth `Authorization: Bearer YOUR_KEY`. Ключ WAIX должен иметь право `messages:write`. Описание всех узлов: [схема сценария](README.md#что-делает-каждый-узел).

В **Prepare request** задайте `connectionId`, `templateName`, `language`. Пример передаёт одну переменную тела — `name`. Состав `components` должен совпадать с вашим одобренным шаблоном.

## Входные данные

Сервер отправляет POST на Test URL или Production URL из вашей установки n8n, с заголовком `X-Workflow-Key` и `Content-Type: application/json`:

```json
{"event_id":"f5bf0474-d4b6-4ca5-bd1b-92e44f3ad0fb","phone":"+77071234567","name":"Аида","whatsapp_consent":true}
```

Сервер сайта проверяет форму и согласие клиента, сохраняет заявку и UUID, затем вызывает сценарий. Не вызывайте n8n напрямую из браузера.

## Ответ и ошибки

HTTP `202` означает постановку сообщения в очередь. Сохраните `data.id`, а доставку проверяйте по вебхукам или журналу WAIX.

Неверные поля отклоняются до обращения в WAIX. Ошибки `401`/`403` требуют проверки ключа и прав. Для `429` учитывайте `Retry-After`. После таймаута отправки сохраняйте тот же `event_id` и тело запроса; новый UUID может создать повторное сообщение или OTP-запрос.

Проверьте сценарий с тестовыми данными, затем включите его и переведите backend на Production URL. Ключи и URL внутреннего вебхука не должны попадать в браузер или общие логи.
