# Отправка OTP через WhatsApp

[Все сценарии n8n](README.md) · [JSON для импорта](otp-send.json)

## Подготовка

Импортируйте `otp-send.json`. Создайте входящий Header Auth `X-Workflow-Key` и отдельный исходящий Header Auth `Authorization: Bearer YOUR_KEY`. Ключ WAIX должен иметь право `otp:send`. Описание всех узлов: [схема сценария](README.md#что-делает-каждый-узел).

Укажите ключ OTP-проекта в credentials узла **WAIX API**. Начните с sandbox. Connection ID и шаблон своего номера для этого продукта не нужны.

## Входные данные

Сервер отправляет POST на Test URL или Production URL из вашей установки n8n, с заголовком `X-Workflow-Key` и `Content-Type: application/json`:

```json
{"event_id":"c6e29497-2fc5-4380-888e-699704be43c5","phone":"+77071234567"}
```

Сохраните полученный `data.id` в серверной сессии пользователя и используйте его в сценарии проверки. `test_code` намеренно удалён из ответа n8n: для серверного теста получите его через авторизованный sandbox API, а не показывайте пользователю.

## Ответ и ошибки

Сохраняйте HTTP-статус и результат API. Sandbox не отправляет реальные сообщения; рабочая отправка зависит от доступности тарифа и одобренного отправителя.

Неверные поля отклоняются до обращения в WAIX. Ошибки `401`/`403` требуют проверки ключа и прав. Для `429` учитывайте `Retry-After`. После таймаута отправки сохраняйте тот же `event_id` и тело запроса; новый UUID может создать повторное сообщение или OTP-запрос.

Проверьте сценарий с тестовыми данными, затем включите его и переведите backend на Production URL. Ключи и URL внутреннего вебхука не должны попадать в браузер или общие логи.
