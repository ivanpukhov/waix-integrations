## Что делает каждый узел

Названия узлов сохранены такими же, как в JSON, чтобы их легко найти после импорта.

| Узел | Назначение |
| --- | --- |
| **Server webhook** | Принимает POST от вашего backend. Доступ защищён Header Auth с заголовком `X-Workflow-Key`. |
| **Prepare request** | Проверяет входные поля, формирует путь API, заголовки и тело запроса. Для сообщений здесь задаются номер WAIX, шаблон и язык. |
| **Valid request** | Направляет корректные данные в API, некорректные — в ответ с ошибкой. |
| **WAIX API** | Выполняет HTTP-запрос с отдельным ключом WAIX. Перенаправления и автоматические повторы отключены. |
| **Return API result** | Возвращает результат и HTTP-статус WAIX. В сценарии отправки OTP убирает `test_code` из ответа. |
| **Invalid request** | Возвращает ошибку проверки без вызова WAIX. |
| **Setup** | Памятка в редакторе; в выполнении сценария не участвует. |

## Два разных секрета

1. Входящий: Header Auth, имя заголовка `X-Workflow-Key`, длинный случайный секрет. Только сервер вашего приложения знает Production URL сценария и этот ключ.
2. Исходящий: Header Auth, имя `Authorization`, значение `Bearer YOUR_WAIX_API_KEY`. Для сообщений — ключ компании `messages:write`; для OTP — ключ соответствующего проекта.

Не используйте один секрет для обеих задач. Не вставляйте ключи в JSON-файл или клиентский JavaScript.

## Тест и запуск

В n8n тестовый webhook обычно работает только во время ожидания тестового события. Для постоянной работы включите сценарий и используйте Production URL, который показывает ваш редактор n8n. Не подставляйте адрес из чужой установки.

История успешных, ошибочных и ручных выполнений отключена, закреплённых данных нет. Если временно включаете диагностику, используйте вымышленные номера и не сохраняйте OTP-коды.

Импорт всех сценариев проверен в n8n 2.40.5. Автоматические проверки: `node --test test/workflows.test.mjs` из корня репозитория. Проверки не отправляют сообщения WhatsApp.
