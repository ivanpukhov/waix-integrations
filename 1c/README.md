# WAIX для 1С: уведомления и OTP

[Все интеграции](../README.md) · [Модуль WAIX.bsl](WAIX.bsl)

Серверный модуль для 1С:Предприятие 8.3.18+. Отправляет шаблоны с текстовыми переменными, читает статус сообщения, отправляет и проверяет OTP. Работает через HTTPS с проверкой сертификата; внешняя компонента не нужна.

## Установка

1. В расширении создайте общий модуль `WAIX`: **Сервер = Да**, **Клиент = Нет**, **Вызов сервера = Нет**. Вставьте код `WAIX.bsl` и проверьте синтаксис в своей версии платформы.
2. Храните ключ WAIX в защищённых серверных настройках с доступом только для фонового задания. Не добавляйте его в форму, пользовательский макет или журнал регистрации.
3. В WAIX подключите номер, получите Connection ID, создайте ключ `messages:write` и одобрите шаблон. Для чтения статуса нужно право `messages:read`.
4. Настройте очередь исходящих уведомлений и фоновое задание. HTTP-запрос не должен выполняться при проведении документа внутри транзакции.

## Шаблон с несколькими переменными

```bsl
Переменные = Новый Массив;
Переменные.Добавить("Иван");
Переменные.Добавить("Заказ №42");
// UUID записан в регистр до отправки; не создавайте его заново при повторе.
Результат = WAIX.ОтправитьШаблонСПараметрамиWAIX(КлючAPI,
    ИдентификаторПодключения, "+77071234567", "order_ready", "ru",
    Переменные, СохраненныйИдентификаторОперации);
```

Порядок переменных должен совпадать с одобренным шаблоном Meta. Пустой массив подходит для шаблона без переменных тела. Если нужны заголовок, медиа или кнопки, расширьте структуру `components` по документации API. Существующая `ОтправитьШаблонWAIX` с одной переменной сохранена.

`ТелефонE164WAIX` удаляет пробелы, дефисы и скобки; 11 цифр с начальной `8` преобразует в `+7…`. Международные номера передавайте с `+` и кодом страны. Не угадывайте страну по короткому локальному номеру.

## Ответ

| Поле | Значение |
| --- | --- |
| `Успех` | Только успешный HTTP-ответ с корректным JSON. |
| `КодСостояния` | HTTP-статус; 0 — ответ не получен. |
| `Данные` | Значение `data` ответа, тип Соответствие. |
| `Ошибка` | Код ошибки API или транспорта. |
| `RequestID` | Идентификатор для поиска запроса в поддержке. |
| `RetryAfter` | Заголовок ожидания при ограничении частоты. |
| `Тело` | Исходный ответ для диагностики. Может содержать данные клиента и sandbox-код; не выводите в общий журнал. |

После `202` сохраните `Результат.Данные.Получить("id")` в регистре. Сообщение принято в очередь. Через `СтатусСообщенияWAIX(КлючAPI, ID)` можно узнать `sent`, `delivered`, `read`, `failed` или `outcome_unknown`.

## Очередь и повторы

Минимальные поля регистра: ссылка на документ/событие, UUID операции, получатель, имя и язык шаблона, сериализованные параметры, время следующей попытки, число попыток, ID сообщения WAIX, статус, request ID.

Сохраняйте запись **до** сетевого вызова. Фоновое задание берёт запись с блокировкой, отправляет запрос и фиксирует результат. Повтор читает прежнюю запись, а не формирует параметры заново из изменившегося документа.

- `400/422`: исправить поля или шаблон, автоматический повтор остановить.
- `401/403`: проверить ключ и права, повтор остановить.
- `409`: под тем же UUID пришло другое тело; сверить регистр.
- `429`: отложить на `RetryAfter`. Если это HTTP-дата, сравнить с текущим временем UTC; не приводить её к числу вслепую.
- `5xx/TRANSPORT_ERROR`: исход может быть неизвестен. Сохранить UUID и тело; ограничить число повторов и передать проблему ответственному после исчерпания лимита.
- `outcome_unknown`: проверить доставку вручную, не создавать новую операцию автоматически.

## OTP

Для OTP создайте отдельный проект и ключ с `otp:send`, `otp:verify`, `otp:read`. Начните с sandbox.

```bsl
Ответ = WAIX.ОтправитьOTPWAIX(КлючПроекта, "+77071234567", UUIDОперации, 300);
// Сохраните Ответ.Данные.Получить("id") на сервере вместе с текущей попыткой входа.
Проверка = WAIX.ПроверитьOTPWAIX(КлючПроекта, IDЗапроса, "012345");
Статус = WAIX.СтатусOTPWAIX(КлючПроекта, IDЗапроса);
```

Срок кода — от 60 до 600 секунд. Код всегда строка, включая начальные нули. Не передавайте sandbox `test_code` пользователю. Выдавайте доступ только после успешной проверки кода и проверки принадлежности ID текущему пользователю.

## Приёмка в вашей конфигурации

Модуль прошёл статический анализ BSL Language Server 1.0.7. Нужны также проверки синтаксиса и запуска на вашей платформе 1С: здесь не поставляется лицензированная среда 1С. До включения фонового задания проверьте кириллицу и кавычки в переменных, номер в локальном формате, отсутствие согласия, один запрос и его повтор с тем же UUID, неверный ключ, таймаут, доставку и ошибку Meta. Проверку согласия и отказов реализуйте в процессе формирования очереди; модуль не может узнать их по одному телефону.
